# 로드맵 설계: 0.6 → 0.7 → 0.8 → 1.0 (2026-09-01)

> 상태: 사용자 승인 완료. 구현 계획은 0.6 트랙 착지 시 별도 계획 문서로 작성.

## 목표

기능적으로 성숙한 상태(4호스트, 타입 패리티, 계약 게이트)에서 다음 1년의 방향을
버전-테마 마일스톤으로 정의한다.

- **축 우선순위**: 사용자 성장(DX+채택) > 개발 견고성 > selling point(발전 방향 분석 포함)
- **타깃 우선순위**: 멀티호스트 팀 > Tauri/RN 앱 개발자 > 백엔드/서버 개발자
- **시간 지평**: 1년+ 장기 비전까지
- **실행 리듬**: 트랙 단위 착지(기존 병렬 3트랙 방식)를 버전 테마에 귀속시키는 하이브리드

## North-star (1년+)

> Rust 함수 하나를 정의하면, 데스크톱·모바일·서버 어디서든 **계약이 검증된** 타입
> 안전 클라이언트로 호출된다 — 팀은 호스트별 어댑터 코드를 한 줄도 쓰지 않는다.

1.0 = 이 문장의 모든 명사가 예외 없이 증명된 상태:

- **"계약이 검증된"**: `rustra diff` CI 게이트 + contract hash 런타임 감지 + OTA 스키마
  호환이 기본값
- **"어디서든"**: 4호스트가 전부 Runtime verified + 실기기 증거까지
- **"한 줄도 쓰지 않는다"**: 단일 화살 코드젠(생성 진입점 규칙)이 모든 호스트에서 동일

### 1년 세 부동축

1. **채택 전환** — 첫 성공까지의 시간을 계속 줄인다. 온보딩 게이트(init→doctor→codegen→demo)가
   CI에서 항상 green이고, 스크래치→첫 호출이 문서대로만 따라가면 되는 상태.
2. **증거의 등급화** — "지원한다"와 "증명됐다"의 거리를 계속 좁힌다. 호환성 매트릭스의
   증거 수준이 거짓말을 하지 않는 것. iOS 실기기, Windows host 수준 실증이 과제.
3. **생태계 개방** — 확장이 rustra 내부가 아니라 안정된 API로 이뤄지는 것. 서드파티가
   adding-host 가이드만 따라 호스트를 추가할 수 있는 수준.

### 보조 지표 3개

- 온보딩 게이트 E2E 시간 (CI 측정, regression 감지)
- 증거 커버리지 = 호환성 매트릭스의 "Runtime verified" 셀 비율
- 계약 게이트 커버리지 = schema 표면 중 diff가 잡아내는 비율

## Selling point 발전 방향 (0.6에서 확정 커밋)

- 현재 강점: 와이어 크기(JSON 대비 11.8× 작음), 계약 게이트(diff+contract hash),
  멀티호스트. 이 중 **계약 게이트가 유일하게 경쟁 도구에 전혀 없는 것** → 와이어 숫자
  경쟁이 아니라 계약 소유를 더 깊게 하는 것이 발전 방향.
- 약점: ① 생태계 인지도·문서 언어(한국어 중심), ② 실기기 증거 부재로 simulator 영수증에
  머무는 점, ③ 배치 항목별 취소 등 세부 시맨틱.
- 결론: **"유일한 것(계약 소유)을 더 깊게 + 증거를 실기기로 격상"** — 0.7(계약 강화)과
  1.0(증거 완결)으로 이어지는 축.

## 0.6 "완성도" (지금~약 1개월, 축: 사용자 성장)

테마: **비교표의 ✅가 진짜가 되는 릴리스**.

### T1. 버전 스큐 해소 + 발행 (즉시, 저위험 고임금)

- testing/devtools/react 0.4.1이 `@rustra/types ^0.5.0`에 의존하는 스큐를 changeset(minor)
  으로 해소. 대기 중 changeset과 함께 발행 PR #51 처리.
- 루트 CHANGELOG 0.2.0 정지분 정리 (0.3→0.6 와이어 breaking 요약).
- 성공 기준: npm 설치 → 어댑터 조합이 peer resolution 에러 없이 통과.

### T2. 이벤트 표면 완결 (가장 큰 사용자 가치 갭)

- Node/Bun `subscribeEvent` — node는 현재 drainEvents 폴링만 제공 → push 지원.
- 타입 안전 이벤트 코드젠 — schema.json에 events 섹션 추가. `rustra diff`가 이벤트
  breaking change도 잡도록 계약 게이트와 정합 (open question: events 섹션과 diff 게이트
  정합 방식).
- Tauri 채널 표면.
- 순서 근거: 타깃 1순위가 멀티호스트 팀이므로 "이벤트가 Tauri에서만 되는" 비대칭 제거 선행.

### T3. CLI 인체공학 1차 (구조적 수정 먼저)

- 4곳 중복 arg-parser 통일 → `--help` 전면 지원, exit 코드 구분(usage 오류=2),
  `--flag=value` 균등 지원이 같은 자리에서 해소.
- init 안전화: 기존 파일 덮어쓰기 확인, 스캐폴드에 .gitignore/tsconfig 추가.
- config 오타 키 silent ignore → 검증 에러 ("코드 접두어 + 경로 + fix" 3요소 헬퍼).
- doctor의 `--format json` 패턴을 codegen/diff/dev에 전파 → CI 통합 표면 통일.

### T4. 문서 정확성 스윕 + 게이트 고정

- HIGH 6건: README 퀵스타트(인자 없는 init 실패), 스칼라 멀티파라미터 자기 모순 예제,
  폐기된 `divide(engine,...)` 시그니처, 생성 코드 샘플 세대 불일치, CONTRIBUTING 릴리스
  섹션 폐기, 루트 CHANGELOG 정지.
- **프로세스 게이트로 고정**: docs 예제 검증을 CI에 추가 — "문서-현실 불일치 반복 패턴"을
  게이트로 종결. (검증 4계율: 계약은 산문이 아니라 게이트로.)

## 0.7 "신뢰" (1~3개월, 축: 개발 견고성)

테마: **무언가 깨졌을 때 사용자가 알 수 있는 릴리스**. 성공 경로는 0.6에서 닦고,
실패 경로의 품질을 올린다.

### 착지 항목

- **에러 품질**: normalizeRustraError cause 체인 보존, 에러 클래스 계층(Timeout/Cancelled
  서브클래스, minor 내 opt-in 설계로 breaking 회피), retryable 소비 유틸(withRetry).
- **디버깅 지원**: RUSTRA_DEBUG 계열 env — 와이어 덤프, NDJSON 파싱 실패 라인 보존,
  응답 셰이프 검증 경고.
- **Rust 저작면 진단**: 코드젠 unknown 폴백 무경고 제거(타입명·명령명 보고), fn doc comment
  → TS JSDoc 전달(죽은 `__RUstra_doc_` 상수 살리기), 커스텀 에러 enum → TS 코드 매핑
  (thiserror 패턴 문서화).
- **검증 커버리지**: mock 엔진 출력 검증, 계약 게이트가 필드 추가/삭제·타입 변경 감지로
  강화, iOS 실기기 증거 격상.
- **React 훅**: bigint inputKey 크래시 수정(useCommand — 생성 타입이 `number | bigint`
  인데 JSON.stringify 기반), Suspense 캐시/무효화 1차.

### 다방면 분석

| 관점          | 효과                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| DX            | 첫 성공 후 2주차 좌절(디버깅 불가, 에러가 말 안 해줌) 제거 — 채택 전환율 2차 병목                                               |
| 견고성        | 이 버전의 주인공. 계약 게이트가 "이름만 검사"에서 실질 검증으로 격상 — selling point 핵심 자산 두터워짐                         |
| Selling point | "유일한 것을 더 깊게" 전략의 핵심 실행 — 계약 소유가 와이어 숫자보다 방어 가능한 차별점이라는 분석의 실증                       |
| 리스크·비용   | 에러 클래스 계층은 TS 표면 breaking 가능 → opt-in 설계. iOS 실기기는 일정 불확실성 최대 항목 — 별트랙 분리 가능, 테마 붕괴 없음 |
| 의존성        | 0.6 이벤트 코드젠(events 섹션) 위에 계약 강화가 얹힘 — 순서 고정, 0.6 없이 착지 불가                                            |

## 0.8 "확장" (3~6개월, 축: 사용자 성장 2라운드)

테마: **4호스트를 넘어서**. 멀티호스트 팀 타깃의 논리적 연장.

### 착지 항목

- **신규 호스트**: Electron 어댑터 — adding-host 가이드를 실제로 따라 만드는 첫 사례
  (가이드의 dogfooding 검증). Deno는 필요성 확인 후 결정.
- **React 훅 2세대**: tanstack-query 격차 해소 — Suspense 통합, 캐시 무효화, useEvent
  스트림 결합 (0.7 1차의 완성).
- **WASM 코어**: 브라우저 직결 표면. 승격 여부는 0.7 종료 시점 채택 신호로 결정 (스파이크
  선행 — 코덱 중복 문제 재발 방지).
- **배치 항목별 취소**: "명시적 미지원 계약"을 실제 시맨틱으로 승격 (백엔드 타깃 3순위 유지).

### 다방면 분석

| 관점          | 효과                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| DX            | 훅 2세대가 "Rust 백엔드 + React 프런트" 팀의 기본 선택지가 됨 — 프레임워크 생태계에 붙는 것이 채택의 가장 짧은 경로                   |
| 견고성        | Electron = adding-host 가이드의 dogfooding. 가이드만 따라 만들 수 없으면 확장 API가 아직 안정이 아니라는 증거 → 문서-현실 일치 게이트 |
| Selling point | "단일 코어 × N호스트" 비교표가 Node/Bun/Tauri/RN/Electron(+WASM)로 확대 — 멀티호스트 정체성의 물리적 증명                             |
| 리스크·비용   | WASM은 코덱 3벌 문제 재발 가능 → 스파이크 선행. Electron 이벤트 푸시는 0.6 설계를 재사용하면 저비용                                   |
| 의존성        | 0.6 이벤트 설계 → Electron 이벤트 재사용. 0.7 훅 1차 → 0.8 2세대. 역순 불가                                                           |

## 1.0 "안정 선언" (6~12개월, 축: 전 축 수렴)

테마: **약속을 문서가 아니라 게이트로 선언** — 검증 4계율의 최종 적용.

### 착지 항목

- **호환성 보장 강화**: EngineClient 계약을 semver 보장 대상으로 승격 (versioning-policy의
  experimental 셀 소진).
- **증거 완결**: iOS/Android 실기기 증거, Windows host 수준 실증, 매트릭스 "별도" 셀 제로화.
- **폐기 절차 시행**: 첫 공식 deprecation 사이클 실전 운용 (0.4→1.0 사이 폐기된 표면 정리).
- **채택 패키지**: 영어 문서 완성(한국어 중심 탈피), 서드파티 호스트 제작 사례 1건, 첫 외부
  기여자 수용 준비(CONTRIBUTING 온보딩 경로 검증).

## 상시 실행 리듬

- 트랙 단위 착지는 유지하되 **버전 테마에 귀속** — 테마를 벗어나면 다음 버전 후보로 큐잉.
- 병렬 트랙 시 파일 충돌 예상되면 merge-tree 선검증 (기존 성공 패턴).
- 발행은 changeset이 쌓인 분량으로 판단, 발행 PR 머지는 사용자 승인 (기존 규칙 유지).

## 전 버전 공통 게이트

- 모든 계획 문서의 체크박스는 착지 시 즉시 갱신 (문서-현실 불일치 반복 패단).
- "지원"과 "증명"의 언어 구분 유지 — 매트릭스 증거 수준은 거짓말을 하지 않는다.
