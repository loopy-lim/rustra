**Files:**

- Modify: `examples/calculator/src/bin/loop-stdio.rs` (레퍼런스 런타임 — `set_event_sink` 설치)

**프로토콜 설계 (기존 프레임 규약 확장):**

- 바이너리 모드 프레임 = 6바이트 헤더(cmd id u16 + 길이 u32) + 본문 (`node-loop.ts:100-135` 기존 규약)
- 응답 프레임과 구분되는 **예약 cmd id `0xfffd`** 를 푸시 이벤트 프레임으로 정의 (`0xfffe`는 drain — `node-loop.ts:40`)
- 본문 = 1줄 JSON `{"name":..., "payload":<string JSON>, "seq":<number>}`

**Step 1:** loop-stdio serve 루프에서 `pkg.set_event_sink(Some(Arc::new(...)))`로 싱크 설치 — 싱크 클로저가 stdout mutex를 잡고 6바이트 헤더(`0xfffd`, len) + JSON 본문을 쓴다. `--serve` 플래그로 opt-in 여부는 기존 drain 지원 방식(`__drainEvents` 특수 커맨드 :69-82 등)과 일관되게 결정.
**Step 2:** Rust 테스트: 싱크가 불리면 stdout 버퍼에 0xfffd 프레임이 기록됨을 단언 (in-process 버퍼 주입 또는 스레드 emit 후 프레임 파싱).
**Step 3:** `cargo test -p rustra-calculator-example` PASS 확인.
**Step 4:** 커밋 `feat(examples): loop-stdio 런타임이 이벤트 싱크 푸시 프레임(0xfffd) 전송`.

> 안전 규칙: 싱크 설치 중 emit은 버스를 우회하므로(Rustra 코어 보장, `package_events.rs:33-40`) 푸시/폴링 이중 수신 문제는 코어가 이미 해결한다. 폴링 폴백을 위해 drain(`__drainEvents`/0xfffe) 경로는 그대로 유지 — 단, 싱크 설치 중엔 버스에 쌓이지 않으므로 **푸시 모드에서는 drain이 빈 값을 반환**하는 정상 동작임을 테스트로 고정.
