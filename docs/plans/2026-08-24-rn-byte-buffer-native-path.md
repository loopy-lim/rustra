# React Native direct byte-buffer path

Status: implemented and simulator-verified on 2026-08-24

## Goal

Remove byte-array element conversion and redundant response copies without
changing the generated Promise API, error semantics, or old-native fallback.
The optimization is deliberately narrower than general collection support.

## Eligibility

All three gates must agree before capability bit 3 is exposed:

1. Generated input and output schemas each contain exactly one required
   `Vec<u8>` field and no other properties.
2. Generated C++ metadata contains a direct input/output buffer codec for the
   stable numeric command id.
3. Rust registers that command explicitly with
   `PackageBuilder::buffer_command` or `buffer_command_fn`.

Schema shape alone never opts a handler into the ownership ABI. The explicit
Rust registration prevents an old or dynamic registry from advertising a path
whose handler cannot consume and return an owned byte vector.

## Public contract and fallback

Generated byte fields accept `Uint8Array | ArrayBuffer | number[]`.

- `Uint8Array` and `ArrayBuffer` use `invokeTypedBuffer` when capability bit 3
  is available and no invocation options are present.
- A one-byte typed-array subview preserves `byteOffset` and `byteLength`.
- `number[]`, options-bearing calls, missing methods/capabilities, and command
  id/name mismatches use the existing positional/by-id/generated route.
- Old native modules remain compatible because the new method and capability
  bit are optional.
- Synchronous native throws become Promise rejections, matching other
  generated commands.

DataView and multi-byte typed arrays are rejected. Detached storage,
non-integral/out-of-range values, invalid view bounds, null ABI outputs, and
unknown direct handlers fail closed.

## Ownership and lifetime

The synchronous host function borrows the JS input pointer only until
`rustra_ffi_invoke_buffer` returns. `Package::invoke_buffer` copies that span
into the owned Rust input before calling user code; no JS pointer crosses the
handler boundary.

On success, the Rust output `Vec<u8>` becomes an exact boxed slice and its
`(ptr, len)` is transferred to `RustOwnedMutableBuffer`. Hermes retains the
shared `MutableBuffer` for the JS `ArrayBuffer` lifetime. Its destructor calls
`rustra_ffi_free_owned_bytes` exactly once. The finalizer owns no JSI `Runtime`,
`Value`, or `PropNameID`, so it may run after an RN reload without touching a
superseded runtime.

Native installation itself is marshalled through React Native's `CallInvoker`.
The TurboModule promise method runs on a native module queue and must not mutate
Hermes through a raw `Runtime*`; doing so reproduced an `EXC_BAD_ACCESS` in
Hermes `TransitionMap` during reload. A process-global `ArrayBuffer` constructor
handle was also removed because JSI handles may not cross Runtime lifetimes.

The direct allocation has no legacy FFI header and must never be passed to
`rustra_ffi_free`. Debug builds track allocation kind as well as pointer and
length, aborting on double free, wrong length, or cross-allocator free. Error
buffers use the same owned allocator but are converted and freed immediately
instead of becoming a JS `ArrayBuffer`.

Empty buffers keep a valid owned allocation contract with length zero. Failure
while constructing either the C++ owner or JSI `ArrayBuffer` releases the Rust
allocation through RAII.

## Copy accounting

For the benchmark echo command:

| Stage                      | Nitro | Rustra direct |
| -------------------------- | ----: | ------------: |
| Borrow/read JS input       |     0 |             0 |
| Create fresh native output |     1 |             1 |
| Native output to JS buffer |     0 |             0 |
| Bulk copies per invocation | **1** |         **1** |

Nitro copies the input into a fresh `ArrayBuffer`. Rustra copies the borrowed
input into the owned Rust vector, lets the echo handler move that vector into
its output, then exposes the same allocation to JSI. General transforming
handlers may allocate differently, but the bridge adds no response copy.

`#[serde(with = "rustra::byte_buffer")]` separately selects Serde's contiguous
byte API for the normal postcard path while preserving the existing postcard
wire and JSON `number[]` representation.

## Limits and errors

The direct path computes the same wire size as the postcard request:

`2-byte command id + postcard uvar length + data length`

It compares that size with the dynamic Rust FFI limit and returns
`payload.too_large` before the handler runs. With the default 1 MiB limit, the
largest three-byte-length payload is 1,048,571 data bytes. A full 1 MiB data
buffer is intentionally rejected because its wire frame is five bytes larger.

## Simulator performance receipt

Environment: iPhone 17 Simulator, iOS 26.2, Hermes, React Native 0.81.5,
Expo 54, Release build, rotating Nitro/Rustra order, and pre-timing byte equality
checks. The table reports the median of three run-level average times.

| Payload    | Warmup / timed | Nitro median | Rustra median | Paired ratio median |
| ---------- | -------------: | -----------: | ------------: | ------------------: |
| 64 KiB     |       50 / 500 |     9.256 us |      8.644 us |              0.934x |
| 1 MiB wire |       20 / 200 |    87.979 us |     89.836 us |              1.013x |

Before the external-output ownership transfer, Rustra measured 24.174 us and
169.315 us respectively, or 2.344x and 3.644x Nitro. The final rerun after the
JS-thread installation fix still shows parity for these payloads; it is not an
iOS-device or Android claim. One 64 KiB run had a transient Nitro-only slowdown,
while Rustra remained within 8.456–8.792 us across all three runs.

## Release gates

- Bun 1.4 runs JavaScript and app tests.
- Rust unit/integration tests cover empty, error, limit, ABI, allocator-kind,
  schema eligibility, and ownership transfer boundaries.
- TypeScript tests cover subviews, empty buffers, old-native fallback,
  `number[]`, options, id mismatch, route cache reset, and rejected native
  throws.
- C++ tests cover partial views, invalid bounds, generated capability, fresh
  `ArrayBuffer` output, and direct result shape.
- The development reload probe keeps a 64 KiB Rust-owned `ArrayBuffer` and a
  60-second native async call alive across every Runtime replacement; it passed
  30/30 consecutive reloads after the installation-thread fix.
- iOS Release build/install/launch, same-process reload stress, full workspace
  checks, and React Doctor 100/100 are required before merge.
