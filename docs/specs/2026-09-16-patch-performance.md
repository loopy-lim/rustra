# 0.10.2 성능 패치 SPEC

관련 로드맵: [P1–P6 / G0](2026-09-14-rustra-roadmap.md), [기준선 PLAN](../plans/2026-09-14-g0-performance-baseline.md).

## 문제와 범위

0.10.1은 재귀 스키마의 강한 참조 순환을 제거했으나 재귀 명령을 중간 `serde_json::Value` 경로로 보낸다. 2026-09-16 macOS arm64 사전 측정에서 실제 `Package::invoke_frame` 재귀 깊이 1/8은 약 0.83/4.56 µs다. 이 측정은 시작점이며 최종 개선 주장은 독립 프로세스 반복 비교로 확정한다.

이 패치는 공개 API, FFI, wire, 지원 등급을 유지하면서 재귀 codec, optional 필드 임시 버퍼, struct 필드 탐색과 sequence 용량 확장의 불필요한 비용을 줄인다. 다른 병목은 동일 환경 측정에서 효과와 회귀 여부가 확인될 때만 포함한다. 0.10.1은 이미 공개되었으므로 발행 대상은 0.10.2다. npm은 변경이 있는 패키지만 기존 독립 버전 정책을 따른다.

## 설계

- IR의 역참조는 계속 `Weak`다. 컴파일된 codec이 재귀 대상의 소유권을 별도 보관하여 adapter가 호출 동안 유효한 참조를 빌린다. 노드가 소유자 테이블을 참조하지 않으므로 강한 순환을 만들지 않는다. 호출마다 스키마 스캔이나 재귀 노드별 `Arc` 복제는 피한다.
- 재귀 struct/option/seq/map/외부 태그 enum은 지원 판정과 수명 검증을 거쳐 direct serde 경로를 사용한다. 내부 태그/untagged 및 const 검증이 필요한 스키마는 Value 경로를 유지한다. 입력·출력 중 어느 한쪽에 재귀 스키마가 있으면 양쪽 codec의 direct serde 실패에 기존 Value 경로를 적용한다. 명령이 원래 양쪽 모두 Value를 사용했던 경우의 호환성을 유지한다. 스키마가 구별하지 못하는 중첩 optional·flatten·숫자 map 키 등의 호환성을 보존하며 핸들러를 재실행하지 않는다. 잘못된 입력은 Value 경로에서도 같은 제한을 적용한다.
- optional 필드 presence는 현재 항상 1인 경우 값보다 먼저 직접 쓰고 별도 버퍼를 제거한다. 생략 필드 presence 0, None의 option tag, 크기·깊이 제한 및 오류 계약을 유지한다.
- struct 직렬화는 예상 다음 필드와 일치할 때 O(1)로 찾고, 생략·이름 차이가 있는 경우 기존 검색을 사용한다.

- sequence 역직렬화의 초기 용량 힌트는 선언 원소 수와 남은 입력 바이트 중 작은 값으로 제한한다. 잘린 입력이 큰 선할당을 유발하지 않게 하고 정상 배열의 반복 재할당을 줄인다.

## 수용 기준

1. 재귀 direct 경로의 값과 바이트가 기존 Value codec과 일치하며 재귀·상호재귀 그래프는 마지막 codec 소유자가 사라지면 해제된다.
2. 잘못된 입력, trailing bytes, max_depth/max_bytes, caller buffer 부족, optional 생략 및 None, 이름 변경, enum/map/seq를 회귀 검사한다.
3. 동일 벤치 소스를 기준판 0.10.1과 후보판에서 사용하고, 독립 프로세스 최소 5회씩 교차 실행한다. 재귀·optional·넓은 struct와 기존 scalar/map/oneOf 대조군을 포함하고 반복 중앙값, 원시 추정값, 환경·소스·실행 파일 hash를 남긴다.
4. 재귀 경로의 반복 중앙값을 20% 이상 낮추는 것을 목표로 하며, 대조군의 반복 확인된 10% 초과 회귀를 발행하지 않는다. 할당 횟수는 실행 경로에서 별도로 측정하고 시간 벤치에 계측 overhead를 섞지 않는다.
5. Rust 테스트, 공개 API/아키텍처 검사, 동일 발행 SHA의 CI/Miri/Sanitizer/Fuzz와 레지스트리 감사를 통과한다.

## 증거 경계

코어 호출의 개선은 앱 p95·실기기·에너지 개선을 뜻하지 않는다. Linux Alpha 유지. 로드맵의 외부 사용자 평가, 실제 앱 수명주기·장시간 검증, 기기별 성능은 이 패치만으로 완료 처리하지 않는다.

## 추가 수용 기준: 분기 트리와 탐색 (사용자 요청)

단일 연결 재귀만으로 복잡한 트리의 성능을 일반화하지 않는다. 문자열·optional·enum·map·자식 배열이 섞인 트리를 사용하고 균형 트리(31/255/1,023/8,191 nodes, 기본 한도 내에서 수용되는 경우), 넓은 트리(1,025 nodes), 한쪽으로 치우친 트리(기본 depth 한도 내), payload가 큰 트리를 비교한다. 기존 0.10.1과 후보에 같은 fixture를 적용한다.

전체 트리 echo, 트리 전체를 보내는 마지막 노드 DFS 탐색 요청, Rust에 보관한 트리의 ID 기반 조회 요청, 메모리에 이미 올라온 트리의 순수 DFS를 각각 측정한다. ID 조회는 기존 명령 API와 공유 소유권을 사용하며 새 런타임 API를 추가하지 않는다. 초기 보관 비용은 반복 조회 측정에서 제외한다. 노드 수·깊이·fanout·입출력 bytes·할당을 남기고 최소 5회 교차 비교한다. 탐색은 모든 노드를 방문하는 최악 경로로 결과와 방문 수를 사전에 확인한다. 전체 입력 역직렬화와 필요 없는 출력 재전송의 비용을 탐색 알고리즘 자체와 구분한다. 기본 깊이 한도 초과 요청은 정상 오류로 거부되는지 확인하며 한도를 완화해 성공을 꾸미지 않는다. 이 fixture는 앱 고유 인덱스·캐시·임의 객체 graph나 cyclic reference의 성능 증거가 아니다.
