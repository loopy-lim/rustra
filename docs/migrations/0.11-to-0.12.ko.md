# DX 업그레이드: Rust 0.11 → 0.12

이번 릴리스는 `rustra init my-project --setup`, 반복 실행 가능한 `rustra setup --run`,
Bun 스캐폴드, 호스트 수명 관리 개선과 RN·Tauri 설정 지원을 추가한다.
패키지 버전은 독립적으로 관리하며 대상 버전은 다음과 같다.

| 패키지                                          | 이전   | 대상   |
| ----------------------------------------------- | ------ | ------ |
| Rust `rustra`, `rustra-macros`, `rustra-naming` | 0.11.0 | 0.12.0 |
| `@rustra/cli`                                   | 0.11.3 | 0.12.0 |
| `@rustra/node`, `@rustra/bun`                   | 0.10.2 | 0.11.0 |
| `@rustra/react-native`                          | 0.9.2  | 0.10.0 |
| `@rustra/tauri`                                 | 0.9.3  | 0.10.0 |
| `@rustra/types`                                 | 0.12.0 | 0.12.1 |

레지스트리 발행을 확인하기 전 버전 파일은 릴리스 후보를 나타낸다. 새 RN 정적 브릿지와
Tauri 헬퍼는 Rust 0.11.0에 없는 API를 요구하므로 Rust를 먼저 발행한다.
CLI 스캐폴드의 최소 Rust 범위도 `rustra = "^0.12.0"`으로 함께 올린다.

## 기존 앱 업그레이드

1. Rust와 사용하는 호스트의 npm 패키지를 위 대상 버전으로 올린다. `rustra`와
   `rustra-macros`의 호환성을 유지하고 Cargo·npm lockfile 변경도 커밋한다.
   새 단일 필드 명령의 생성 코드에는 `@rustra/types` 0.12.1 이상이 필요하다.
2. `rustra doctor --config rustra.json`, `rustra codegen --config rustra.json`,
   `rustra codegen --config rustra.json --check`를 순서대로 실행한다. 생성 TS·C++ 파일과
   소유권 manifest를 함께 커밋한다. deprecated 타입 alias는 계속 제공하지만 새 코드는
   명령 시그니처에 표시된 인라인 타입을 사용한다.
3. 네이티브 코어를 다시 빌드한다. RN은 네이티브 브릿지와 앱도 함께 다시 빌드한다.
   새 정적 브릿지는 `rustra_ffi_invoke_frame_owned`를 직접 링크하므로 JS OTA만으로는
   이 심볼을 공급할 수 없다. hot-core의 구형 fallback이 기존 정적 앱의 호환성을
   보장하지는 않는다.
4. 실제 사용하는 호스트에서 명령·이벤트·채널을 확인한다. 설정 지원 성공과 실제
   기기·WebView 실행 검증은 별개다.

Node·Bun의 `rustra setup --run`은 생성·설치·빌드·호출을 순서대로 실행한다.
실패하면 출력된 setup 명령을 다시 실행한다. 수정한 프로젝트를 `init --force`로
다시 만들 필요는 없다. RN은 `rustra:ios`·`rustra:android` 준비 스크립트를 추가하며,
Tauri는 남은 등록 절차를 출력한다. 네이티브 플랫폼 도구는 여전히 필요하다.

이벤트가 있는 Node 프로젝트는 영속 `serve` 런타임을 사용한다. 사용자 정의
`node.args: ['invoke']` 설정은 `serve`로 바꾸고 생성 NDJSON 런타임의 계약·capability·
이벤트 drain 프로토콜을 구현한다. 이벤트가 없는 프로젝트는 기존 일회성 기본값을 유지한다.

개발 감시 API를 직접 호출하는 도구는 프로젝트 입력을 지우기 전에 `await handle.dispose()`를
호출한다. 종료 요청은 감시와 소유 Cargo 작업을 즉시 취소하고, 반환 Promise는 남은 작업과
출력 스트림의 정리를 기다린다. 기존 반환값 무시 호출도 감시를 중단하지만 정리 완료를
기다려야 하는 호출부는 Promise를 await한다.

## Tauri 등록과 이벤트 전송

새 Tauri 생성 엔트리는 호출 전에 `rustra_contract_hash`를 확인한다. 생성 헬퍼로
Rustra 0.12의 엔드포인트를 등록한다. 앱 자체 네이티브 명령도 있다면 마지막 핸들러
설치에 `with_app_commands`를 사용하고 기존 builder의 플러그인·상태를 유지한다.
그 뒤 `.invoke_handler(...)`를 호출하면 앞서 설치한 핸들러가 교체된다.

글로벌 전송 자동 감지는 `withGlobalTauri` 설정이 필요하다. `invoke`를 직접 주입하는
방법도 계속 지원한다. 사용자 정의 `JsonDispatch`는 strict 검증을 위해 선택한 producer의
실제 해시를 반환하는 `contract_hash()`를 구현한다. 기본값에는 확인 가능한 계약이 없다.
의도적으로 구형·사용자 정의 전송을 쓰는 경우 계약 검증의
`warn`·`off`를 선택할 수 있지만, 누락된 네이티브 API를 제공하는 설정은 아니다.
실제 WebView의 디코딩된 이벤트 값이 기본이다. JSON 문자열을 보내는 구형 주입 전송은
`payloadEncoding: 'serialized-json'`을 명시한다.

## 수정한 생성 파일과 롤백

코드젠은 이전 소유권 manifest로 변경 없음을 입증한 오래된 파일만 지운다.
수정되었거나 소유권이 없는 파일 때문에 중단되면 해당 파일과 출력된 복구 안내를
검토한 뒤 재시도한다. 출력 디렉터리 전체를 삭제하지 않는다.

롤백할 때는 npm·Cargo manifest 범위, lockfile, 생성 파일, 네이티브 앱 아티팩트를
함께 복원한다. `^0.12.0` 범위는 `cargo update --precise 0.11.0`으로 만족할 수 없으므로
이전 Rust 범위를 먼저 복원한다. 공개 버전은 덮어쓸 수 없으며 수정 버전을 발행하거나
이전 npm 태그로 복구한다.
