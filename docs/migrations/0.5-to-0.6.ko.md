# 0.5에서 0.6으로 마이그레이션

0.6은 Rust crate 라인(`rustra`, `rustra-macros` 0.5 → 0.6)의 pre-1.0 minor
릴리스이며, 안정화 트랙을 싣는다: 새로운 선택적 `rustra.json` 섹션, 발행된
JSON Schema 를 통한 에디터 지원, 다중 타깃 `rustra doctor`, 정식 호환성
게이트. 대부분의 변경은 추가 전용(additive)이라 기존 유효 `rustra.json`은
그대로 로드되며 wire·계약 해시·FFI 표면은 하나도 움직이지 않는다. 유일하게
계획이 필요한 동작 변경은 doctor 의 신규 빌드 검사로, 망가진 Rust 셋업이
기존 pass 에서 exit 1 로 바뀔 수 있다.

## 1. 버전

```toml
[dependencies]
rustra = "0.6"
rustra-macros = "0.6"
```

npm 쪽은 더 이상 단일 공유 버전이 아니다. 호환성 앵커는 `@rustra/types`이며
모든 어댑터가 `^0.6.0`에 의존한다. 아래에서 설명하는 CLI 기능들은 다음
`@rustra/cli` minor 에 실린다 — 그 발행 전까지는 발행된 CLI의 `init`/`doctor`
출력에 이 기능들이 없다.

## 2. rustra.json — `$schema`, `dev`, `inspector` 섹션

모두 선택적 추가라 기존 config 수정은 불필요하다.

- `$schema`가 이제 config 루트에서 허용된다. 이전에는 fail-closed 알 수 없는
  키 검사에 걸렸다. `rustra init`은 `@rustra/cli` 패키지 안에 실리는 JSON
  Schema(`./node_modules/@rustra/cli/rustra.schema.json`)를 가리키는 값을
  심어, URL fetch 없이 에디터 자동완성·검증이 동작하게 한다. 기존 config 에
  추가는 선택이다.
- `dev`와 `inspector`는 새 선택적 섹션이다. `dev.target`은 `native`(기본) 또는
  `wasm`을 고르고, `dev.wasm`은 `engine`(`wasm3`만)과 `parityGate`를,
  `inspector.onMismatch`는 `diagnose` 또는 `ignore`를 가진다. 로더는
  교차 필드 위반을 하나로 모은다 — 예컨대 `reactNative` 섹션 없는
  `dev.target: "wasm"`은 첫 위반에서 멈추지 않고 누락된 섹션과 잘못된
  `engine` 값을 전부 나열한다.
- 알 수 없는 키는 여전히 fail-closed이며, 알려진 키 집합이 새 섹션들을
  포함해 늘었다. 로더 에러 메시지에 의존하는 테스트가 있다면 "Known keys"
  목록이 새 섹션을 언급하도록 바뀐 점을 감안해야 한다.

```json
{
  "$schema": "./node_modules/@rustra/cli/rustra.schema.json",
  "schema": "./generated/schema.json",
  "output": "./src/generated",
  "node": {}
}
```

## 3. `rustra init` 출력

- 생성 config 는 최소 조합이다: `$schema`, `schema`, `output`, 호스트 섹션뿐.
  이전 템플릿은 `codegen.rustBinary`/`node.rustBinary`를 명시했지만, 폴백
  선택이 scaffold 레이아웃에서 동일한 바이너리를 고르므로(codegen 은
  `generate`, node 는 패키지 바이너리) 키 없이도 프로젝트가 그대로 동작한다.
  후보가 여럿인 레이아웃에서만 키를 다시 넣는다.
- 호스트 섹션은 감지로 고른다: 대상 프로젝트 `package.json`에
  `react-native*` 의존성이 있으면 `reactNative` 섹션을 넣고, 생성 `Cargo.toml`
  이 그에 맞춰 `staticlib` `[lib]` 섹션을 선언한다.
  `--host node|react-native`가 감지를 덮어쓴다.
- `rustra init` 출력을 diff 하거나 파싱하는 스크립트라면 새 키 순서와 형태를
  인지해야 한다.

## 4. `rustra doctor` — 다중 타깃 매트릭스와 신규 빌드 검사

- 호스트 섹션이 2개 이상인 config 는 타깃별 상태 매트릭스
  (`target / build / contract / runtime / notes`)를 얻는다. 한 섹션이 red 여도
  다른 섹션 검사는 계속되며, exit code 는 최악 상태를 반영한다. 호스트 섹션들이 서로 다른 Rust
  백엔드를 가리키면 `config.rust_consistency` 경고("한 프로젝트, 한 계약")가
  나온다.
- 새 `section.<target>.build` 검사는 `node`, `bun`, `reactNative` 섹션에 대해
  수집된다 — 매트릭스가 프린트되지 않는 단일 섹션 config 에서도. 매니페스트
  해석, 단일 패키지 매칭, 필요한 binary/cdylib/staticlib 타깃 존재를
  검증한다. 이 검사들은 required 이므로, 이전에 통과하던 망가진 Rust 셋업이
  이제 doctor exit 1 을 만든다. `rustra doctor`를 부르는 CI job 이 새로
  실패할 수 있다 — 호출을 빼는 대신 근본 빌드 설정(`crate-type`,
  `node.rustBinary`, `bun.rustLibrary` 등)을 고친다.
- 기계 판독 소비자(`--format json`): `checks` 배열에 `section.*.build`와
  `config.rust_consistency` id 가 새로 생기고, `matrix` 필드는 복수 섹션
  config 에서만 나타난다.

## 5. API·FFI·wire — 조치 불필요

- 추가되거나 제거된 FFI 심볼은 없다. 공개 Rust·TypeScript export 목록은 API
  표면 스냅샷 게이트로 고정되고, 내부 항목은 `#[doc(hidden)]`/`@internal`로
  태깅됐다 — export 의 이동은 없었다.
- wire 포맷과 계약 해시 알고리즘은 불변이다. wire 역호환은 관례 대신 golden
  fixture(`packages/types/src/backcompat.test.ts`)로 강제된다.
- `RendererHost` 상태는 변함없다: `#[doc(hidden)]`이면서 deprecated, 0.x
  사이클이 끝날 때까지 유지된다([버전 정책](../versioning-policy.ko.md)
  참고).
- CI 에 core crate 의 wasm32-unknown-unknown 컴파일 check 가 생겼다. 기여자에게만
  영향이 있다.

## 6. 검증과 롤백

```bash
bun install --frozen-lockfile
bun run test:types
bunx --bun @rustra/cli doctor --config rustra.json
bun run test:release-coherence
bun run test:compat
```

[0.3에서 0.4로 가이드](./0.3-to-0.4.ko.md)처럼 앱별로 Node 실제 process, Bun
실제 FFI, Tauri release build 를 검증한다. 롤백은 버전 고정으로 한다:
Cargo 에 `rustra = "0.5"`, package.json 에 이전 `@rustra/*` 범위 — 공통 앵커인
`@rustra/types`와 모든 어댑터를 같은 범위로 함께 맞춘다. crates.io 버전은
삭제·교체할 수 없다.
