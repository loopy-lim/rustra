# DX upgrade: Rust 0.11 to 0.12

This release adds `rustra init my-project --setup` and repeatable `rustra setup --run`,
Bun scaffolds, host lifecycle fixes, and RN/Tauri setup assistance. Package versions
remain independent. The target versions are:

| Package                                         | Previous | Target |
| ----------------------------------------------- | -------- | ------ |
| Rust `rustra`, `rustra-macros`, `rustra-naming` | 0.11.0   | 0.12.0 |
| `@rustra/cli`                                   | 0.11.3   | 0.12.0 |
| `@rustra/node`, `@rustra/bun`                   | 0.10.2   | 0.11.0 |
| `@rustra/react-native`                          | 0.9.2    | 0.10.0 |
| `@rustra/tauri`                                 | 0.9.3    | 0.10.0 |
| `@rustra/types`                                 | 0.12.0   | 0.12.1 |

Version files describe the release candidate until registry publication is verified.
Publish Rust first: new RN static bridges and Tauri helpers require APIs absent from
Rust 0.11.0. The CLI scaffold uses `rustra = "^0.12.0"`.

## Upgrade an existing application

1. Update Rust and the npm packages used by your host to the targets above. Keep
   `rustra` and `rustra-macros` compatible, and commit Cargo/npm lockfile updates.
   New generated one-field commands require `@rustra/types` 0.12.1 or later.
2. Run `rustra doctor --config rustra.json`, then `rustra codegen --config rustra.json`
   and `rustra codegen --config rustra.json --check`. Commit generated TS/C++ files
   and their ownership manifest together. Existing deprecated type aliases remain
   available; prefer the inline types in command signatures for new code.
3. Rebuild the native core and, for RN, the native bridge and application. The new
   RN static bridge links `rustra_ffi_invoke_frame_owned` directly. A JS-only OTA
   update cannot supply this symbol; the hot-core legacy fallback does not make an
   new bridge linked against an old Rust core compatible.
4. Run the application's command, event and channel checks on its actual host.
   Setup assistance does not establish native-device or WebView acceptance.

`rustra setup --run` generates, installs, builds and invokes Node/Bun in order.
Rerun the printed setup command after a failure; do not recreate an edited project
with `init --force`. RN adds `rustra:ios`/`rustra:android` preparation scripts and
Tauri prints its remaining registration steps. Platform tools are still required.

Node projects with events now use a persistent `serve` runtime. Replace a custom
`node.args: ['invoke']` configuration with `serve` and implement the generated
NDJSON contract/capability/event-drain protocol. Projects without events retain
the one-shot default.

Tools using the development watcher API should `await handle.dispose()` before
removing project inputs. Disposal immediately stops watchers and cancels owned
Cargo commands; its promise drains active work and child output. Existing callers
that ignore the return still stop watching, but cleanup callers should await it.

## Tauri registration and event transport

Generated Tauri entries verify `rustra_contract_hash` before invocation. Register
the Rustra 0.12 endpoints with the generated helper. When the app has its own native
commands, use `with_app_commands` for the final handler installation, and preserve
plugins and state on the builder. A later `.invoke_handler(...)` replaces that handler.

Automatic global transport detection needs `withGlobalTauri`; explicit `invoke`
injection remains supported. Custom `JsonDispatch` implementations must override
`contract_hash()` with the selected producer's actual hash for strict verification;
the default returns no verifiable contract. Contract verification `warn`/`off` is available for
an intentional legacy/custom transport, but cannot supply missing native APIs.
Decoded WebView event values remain the default. Legacy injected event transports
that send JSON strings must explicitly select `payloadEncoding: 'serialized-json'`.

## Edited generated files and rollback

Generation removes obsolete files only when the old ownership manifest proves
they are unchanged. If it refuses an edited or unowned file, review that file and
the printed recovery instructions before retrying; do not delete the whole output.

Roll back npm and Cargo manifest ranges, lockfiles, generated files and the native
application artifact together. Restore the previous Rust range before selecting
0.11.0: `cargo update --precise 0.11.0` cannot satisfy `^0.12.0`. Published versions
remain immutable; distribute a corrective version or restore the prior npm tag.
