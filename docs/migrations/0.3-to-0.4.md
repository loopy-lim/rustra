# Migrating from 0.3 to 0.4

0.4 is a pre-1.0 minor release that changes the zero-config entry points of
all four hosts and the release policy together. Do not leave only
`@rustra/types` at 0.3.1 — bump all 9 public npm packages and the 2 Rust
crates to the same 0.4 release line.

## 1. Align versions and the package manager

Set all `@rustra/*` dependencies to `^0.4.0`, and `rustra` and
`rustra-macros` to `0.4`. App installs, codegen, and tests in this repository
are based on Bun 1.4.0.

```json
{
  "packageManager": "bun@1.4.0",
  "dependencies": {
    "@rustra/types": "^0.4.0"
  }
}
```

```toml
[dependencies]
rustra = "0.4"
rustra-macros = "0.4"
```

```bash
bun install
bunx --bun @rustra/cli generate --config rustra.json
bun run typecheck
bun test
```

Remove `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, and npm/pnpm/yarn
-specific scripts from the active app path. Existing caches are not build
inputs and may be deleted, but archive them first if offline reuse matters.

## 2. The common Rust entry point

Rename the entry point that was bound to the mobile name so it fits every
native host.

```rust
// 0.3
rustra::mobile_entry!(my_package);

// 0.4 recommended
rustra::native_entry!(my_package);
```

`mobile_entry!` remains an alias in 0.4, but new code uses `native_entry!`.
Bun needs `cdylib`, React Native needs `staticlib`. If one crate provides
both, declare it as follows.

```toml
[lib]
crate-type = ["rlib", "cdylib", "staticlib"]
```

## 3. Per-host zero-config entry points

Enable only the hosts you use in `rustra.json`. Do not import generated entry
points from different runtimes in the same app at the same time.

```json
{
  "schema": "./generated/schema.json",
  "output": "./generated",
  "node": {},
  "bun": {},
  "tauri": {},
  "reactNative": {}
}
```

### Node

```ts
// 0.3: the app creates the transport and configures it directly
configure(createNodeEngine(customTransport));
import { addNumbers } from './generated/commands.js';

// 0.4: the standard stdio binary is discovered through Cargo metadata
import { addNumbers } from './generated/node.js';
```

For deployment layouts where automatic discovery is impossible, specify
`node.rustBinary` or `RUSTRA_NODE_BINARY`. The default subprocess path is for
development convenience. On the current host matrix, one-shot measured 2.76
ms, the persistent loop 16.86 us, and N-API 1.26 us. Choose the zero-config
one-shot for low-frequency CLIs, the persistent loop for ordinary servers,
and the N-API transport for Node/Electron hot paths with many short calls.

### Bun

```ts
// 0.3: the app manages dlopen, symbol declarations, and response freeing itself
configure(createBunEngine(manualFfiTransport));

// 0.4: the adapter loads a stable ABI and manages response copy and free
import { addNumbers } from './generated/bun.ts';
```

If the library cannot be found, use `bun.rustLibrary` or
`RUSTRA_BUN_LIBRARY`. The returned pointer is copied into a JS-owned
`ArrayBuffer`, and then the Rust allocation is freed exactly once. User
pointers whose zero-copy lifetime cannot be guaranteed are not exposed.

### Tauri

```ts
// 0.3
configure(createTauriEngine(window.__TAURI__.core.invoke));

// 0.4
import { addNumbers, subscribeEvent } from './generated/tauri.js';
```

Set `app.withGlobalTauri` to `true` in the Tauri configuration and wire up
`register_with_events` on the Rust side. Apps whose security policy turns off
the global API keep the explicit path of injecting
`createTauriEngine({ invoke })` directly.

### Expo and bare React Native

```ts
// 0.3: the app maintains the in-app native module and configure manually
configure(createReactNativeEngine(nativeModule));

// 0.4: the generated autolinking package handles JSI install and contract verification
import { addNumbers } from './generated/react-native';
```

Expo development builds and bare RN autolink the same generated package.
Expo Go is not a supported target because it cannot load user-native JSI
modules. Specify `reactNative.rustManifest` only when the Cargo workspace has
multiple candidates.

## 4. Collisions and manual boundaries

- The CLI fails without overwriting when an existing `@rustra/*` package is on
  a different minor line.
- During monorepo development, use `file:`/`workspace:` and root `overrides`
  so every package consumes one source. After publishing, consumer apps move
  every package to the same `^0.4.0` range.
- Multiple binary/library candidates, non-standard output directories,
  disabled global Tauri, and custom N-API transports deliberately require
  explicit configuration.
- Expo Go, environments without native build tools, and target platforms
  without prebuilts do not run from install alone. Rust and the platform
  toolchain are currently required.

## 5. Verification and rollback

```bash
bun install --frozen-lockfile
bun run test
bun run test:compat
bun run test:release-coherence
bun run doctor
```

Per app, verify a real Node process, real Bun FFI, the Tauri release build,
and autolinking plus the native builds for Expo and bare RN. If something
breaks, roll npm back as a whole to the last verified identical minor line.
Because crates.io versions cannot be deleted, pin the Cargo lockfile to the
previous exact version and fix it in the next patch.
