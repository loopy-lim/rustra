# 0.3에서 0.4로 마이그레이션

0.4는 pre-1.0 minor 릴리스이며, 네 호스트의 zero-config 진입점과 릴리스
정책을 함께 바꾼다. `@rustra/types`만 0.3.1에 남겨 두지 말고 공개 npm
패키지 9종과 Rust crate 2종을 같은 0.4 release line으로 올려야 한다.

## 1. 버전과 패키지 매니저 맞추기

모든 `@rustra/*` 의존성을 `^0.4.0`으로, `rustra`와 `rustra-macros`를
`0.4`로 맞춘다. 저장소의 앱 설치, 코드젠, 테스트는 Bun 1.4.0을 기준으로 한다.

```json
{
  "packageManager": "bun@1.4.0",
  "dependencies": {
    "@rustra/types": "^0.4.0"
  }
}
```

```toml
[dependencies]
rustra = "0.4"
rustra-macros = "0.4"
```

```bash
bun install
bunx --bun @rustra/cli generate --config rustra.json
bun run typecheck
bun test
```

`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`과 npm/pnpm/yarn 전용 스크립트는
활성 앱 경로에서 제거한다. 기존 캐시는 빌드 입력이 아니므로 삭제해도 되지만,
오프라인 재사용이 필요하면 먼저 보관한다.

## 2. 공통 Rust 진입점

모바일 이름에 묶였던 진입점을 모든 네이티브 호스트에 맞게 바꾼다.

```rust
// 0.3
rustra::mobile_entry!(my_package);

// 0.4 권장
rustra::native_entry!(my_package);
```

`mobile_entry!`는 0.4에서 별칭으로 남아 있지만 새 코드는 `native_entry!`를
사용한다. Bun은 `cdylib`, React Native는 `staticlib`가 필요하다. 한 crate가
둘 다 제공하면 다음처럼 선언한다.

```toml
[lib]
crate-type = ["rlib", "cdylib", "staticlib"]
```

## 3. 호스트별 zero-config 진입점

사용하는 호스트만 `rustra.json`에서 켠다. 서로 다른 런타임의 생성 진입점을
한 앱에서 동시에 import하지 않는다.

```json
{
  "schema": "./generated/schema.json",
  "output": "./generated",
  "node": {},
  "bun": {},
  "tauri": {},
  "reactNative": {}
}
```

### Node

```ts
// 0.3: transport 생성과 configure를 앱이 직접 수행
configure(createNodeEngine(customTransport));
import { addNumbers } from './generated/commands.js';

// 0.4: 표준 stdio binary를 Cargo metadata로 탐색
import { addNumbers } from './generated/node.js';
```

자동 탐색이 불가능한 배포 레이아웃은 `node.rustBinary` 또는
`RUSTRA_NODE_BINARY`를 지정한다. 기본 subprocess 경로는 개발 편의용이다.
현재 host matrix에서 one-shot은 2.76 ms, persistent loop는 16.86 us, N-API는
1.26 us였다. 저빈도 CLI는 zero-config one-shot, 일반 서버는 persistent loop,
짧은 호출이 많은 Node/Electron hot path는 N-API transport를 선택한다.

### Bun

```ts
// 0.3: dlopen, symbol 선언, 응답 free를 앱이 직접 관리
configure(createBunEngine(manualFfiTransport));

// 0.4: stable ABI 로드, 응답 복사와 free를 어댑터가 관리
import { addNumbers } from './generated/bun.ts';
```

라이브러리를 찾지 못하면 `bun.rustLibrary` 또는 `RUSTRA_BUN_LIBRARY`를 쓴다.
반환 포인터는 JS 소유 `ArrayBuffer`로 복사한 뒤 Rust 할당을 정확히 한 번
해제한다. zero-copy 수명을 보장할 수 없는 사용자 포인터는 노출하지 않는다.

### Tauri

```ts
// 0.3
configure(createTauriEngine(window.__TAURI__.core.invoke));

// 0.4
import { addNumbers, subscribeEvent } from './generated/tauri.js';
```

Tauri 설정의 `app.withGlobalTauri`를 `true`로 두고 Rust 쪽에
`register_with_events`를 연결한다. 보안 정책상 global API를 끄는 앱은
`createTauriEngine({ invoke })`를 직접 주입하는 명시적 경로를 유지한다.

### Expo와 bare React Native

```ts
// 0.3: 앱 내부 native module과 configure를 수동 유지
configure(createReactNativeEngine(nativeModule));

// 0.4: 생성된 autolinking package가 JSI 설치와 contract 검증을 담당
import { addNumbers } from './generated/react-native';
```

Expo development build와 bare RN은 같은 생성 패키지를 autolink한다. Expo Go는
사용자 네이티브 JSI 모듈을 로드할 수 없으므로 지원 대상이 아니다. Cargo
workspace에 후보가 여러 개일 때만 `reactNative.rustManifest`를 지정한다.

## 4. 충돌과 수동 경계

- CLI는 기존 `@rustra/*`가 다른 minor line이면 덮어쓰지 않고 실패한다.
- 모노레포 개발 중에는 `file:`/`workspace:`와 root `overrides`로 한 소스를 쓴다.
  게시 후 소비자 앱에서는 모든 패키지를 같은 `^0.4.0` 범위로 바꾼다.
- 여러 binary/library 후보, 비표준 산출물 디렉터리, global Tauri 비활성화,
  custom N-API transport는 의도적으로 명시 설정을 요구한다.
- Expo Go, 네이티브 빌드 도구가 없는 환경, 프리빌트가 없는 대상 플랫폼은
  설치만으로 실행되지 않는다. 현재는 Rust와 플랫폼 툴체인이 필요하다.

## 5. 검증과 롤백

```bash
bun install --frozen-lockfile
bun run test
bun run test:compat
bun run test:release-coherence
bun run doctor
```

앱별로 Node 실제 process, Bun 실제 FFI, Tauri release build, Expo와 bare RN의
autolinking 및 네이티브 빌드를 확인한다. 문제가 생기면 npm 전체를 마지막으로
검증된 동일 minor line으로 함께 되돌린다. crates.io 버전은 삭제할 수 없으므로
Cargo lockfile을 이전 정확 버전으로 고정하고 다음 patch에서 수정한다.
