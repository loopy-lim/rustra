**`useCommand` 렌더 크래시 제거 (risk audit 2026-09-13 #3)** — 입력 키 파생이 클래스 인스턴스·함수·심볼에서 `TypeError`를 던져 0.7 → 0.8 업그레이드 시 렌더가 크래시하던 문제를 수정했습니다. 이제 구조적 직렬화가 불가능한 값은 throw하지 않습니다. 클래스 인스턴스와 함수는 모듈 수준 `WeakMap`의 인스턴스별 안정 id로(같은 인스턴스는 매 렌더 같은 키, 다른 인스턴스는 다른 키 — WeakMap이라 인스턴스를 붙잡지 않아 누수 없음), 심볼은 description을 포함한 `String(symbol)`에서 파생됩니다(description 없는 심볼은 한 버킷을 공유). 해당 값은 안정적인 직렬화 대상이 아니므로 개발 환경에서 파생 키당 한 번만 `console.warn`을 내보냅니다. 순환 참조는 기존과 같이 `TypeError`입니다.

**느린 명령 결과 폐기 제거 (risk audit 2026-09-13 #4)** — Suspense 캐시의 `pendingTimeoutMs`(기본 30초)가 만료되었을 때 진행 중인 명령의 최종 결과가 캐시에서 버려지고, 5분 TTL 동안 이후 렌더마다 합성 timeout 에러만 재던지던 문제를 수정했습니다. 타임아웃은 기존 UI 계약대로 호출자에게 timeout rejection으로 전달되는 UI 상태 신호일 뿐이며, 캐시는 원래 in-flight promise를 계속 추적합니다. 늦게 도착한 실제 결과(또는 실제 에러)가 캐시에 그대로 반영되어, 다음 렌더는 재호출 없이 실제 데이터를 봅니다.
